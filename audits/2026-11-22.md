## 二、统一事实核验口径

对当代 SQLite 的时间敏感行为，应以固定 release notes、`sqlite_source_id()` 和对应 tag 源码交叉验证，避免用最新 trunk 回写旧版。此次特别复核：

1. SQLite 3.54.1（2026-10-16）与旧维护分支 3.53.6（2026-11-13）的版本先后关系，不能按日历日期判断更高版本号。
2. 3.53.0 的实际查询规划改进（EXCEPT / INTERSECT / UNION sort-and-merge、star-schema join order）已由上轮纠正并收录证据；不应重新误标为未证实。
3. OPFS / opfs-wl / sahpool 的 Worker、COOP/COEP、Web Locks 与锁策略边界；Node.js 官方 WASM 包的内存数据库支持范围。
4. 自定义 VFS tracing 示例不等于透明数据库加密；加密必须保留安全与恢复合同。

权威入口：[SQLite chronology](https://sqlite.org/chronology.html)、[SQLite release history](https://sqlite.org/changes.html)、[SQLite WASM persistence](https://sqlite.org/wasm/doc/trunk/persistence.md)、[Compile-time options](https://sqlite.org/compile.html)。
